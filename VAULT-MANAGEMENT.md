# Vault management — finite implementation and acceptance contract

Unreleased follow-up to 1.0.0; retain version metadata until a separately authorized release. This document appends to CONTRACT.md; existing accepted contracts still govern.

From an already running normal Notes window the File menu exposes **Open Vault…**, **Recent Vaults…**, and **New Vault…**. The current vault's absolute path is discoverable in the window (status, title, or a visible vault label), including when a note is open. Ctrl+O remains the note Quick Switcher. A successful switch may reconfigure the current window or replace it with one normal Notes window within the same process; no terminal, application restart, or manually closing a previous vault is required.

Open Vault uses a native GTK folder chooser titled Open Vault. Selecting an existing readable ordinary directory opens that vault with its notes available, initially with no old note open. Cancel does nothing. Invalid, removed, unreadable, or untraversable destinations report a useful error and retain current vault/text. Selecting the current canonical directory is a no-op that preserves editor state. Resolve the destination and prepare its inventory before relinquishing the current vault. Switching saves dirty text using the existing conflict-safe save semantics; if saving fails, retain the original vault and dirty text and report the failure. Never discard edits implicitly.

Recent Vaults opens a dialog titled Recent Vaults with a keyboard-selectable list of absolute vault paths, most-recent first (maximum ten), plus Open and Cancel. Successful explicit startup/open/create/recents opens record the canonical path, deduplicated, in the user's LCOS Notes config directory outside every vault, and maintain existing last-vault startup behavior. The current vault can appear; opening it is the same no-op. No history file is required on legacy installations; the current last vault must still be usable and selectable. Missing/stale entries must not crash or switch away, may be omitted or visibly rejected, and must not erase surviving entries. Cancellation and failed opens must not promote the failed destination or change last-vault. Persistence I/O failure must not crash or lose edited notes: surface a useful warning, and preserve a valid prior config when feasible. Ordinary normal-sized application configuration is in scope; adversarial config size/concurrency are not.

New Vault opens a dialog titled New Vault with one text entry for the complete new absolute folder path (including its new name), Create and Cancel. This is a plain folder, no proprietary vault structure. The parent must already exist, be writable and traversable; target must not already exist (including a symlink). Create exactly the requested leaf directory and open it empty; do not seed notes or hidden metadata. Empty/relative/root/existing/file/symlink/missing-parent paths are refused without modifying another directory or changing vault/config selection. Creation/switch cancels or failures preserve current edits; in particular save failure must not leave a new vault directory behind. No promise of cross-filesystem transactionality against hostile concurrent writers. If an unavoidable later failure leaves a newly created empty directory, report that exact fact rather than claiming successful opening; never delete user content to roll back.

Switching must discard ALL state belonging to the previous vault only after success: document/undo, reading render, selection, search/tag/backlink/outline/supersession/template/daily state and monitors. No old-vault file event may repopulate the new vault, no old-vault text may be saved to a same-named note in the new vault, and new-note/capture/template actions must continue to use the selected vault. Independent roots may have equal note names and different configuration. Hidden files/Obsidian configuration and all unrelated bytes remain untouched. Startup --vault and last-vault behavior and separate --capture mode retain their established behavior; no switching controls required inside capture windows.

Support ordinary local UTF-8 folder paths including spaces and non-ASCII names on the existing Linux/X11 GTK stack. Embedded newline/control-character folder paths, simultaneous UI windows sharing an editor, malicious same-uid races, permission changes during a successful switch, recursive permission adversaries, power-loss recovery, network filesystems and vault merging/cross-vault link resolution are excluded. Track deferred features/edge input support with entry conditions in BACKLOG.md. No new runtime dependencies, network, accounts or telemetry. Keep C++17/Meson/GTK3, branding and package identity. Update README, handbook vault page, relevant shortcut guidance and man page to describe actual behavior and limits; docs must not call the note Quick Switcher a vault switcher.

Acceptance exercises actual native GUI selection, then verifies disk bytes and config: A→B with same note names and distinct sentinels; dirty-save success and external-change refusal; cancellation and invalid/stale destination; same-vault no-op; create→write→reopen; create collisions and invalid paths; persisted MRU/dedup and no-argument restart; post-switch filesystem event isolation; Ctrl+O remains within selected root. Existing tests are unchanged; test harness changes are caller-owned.
